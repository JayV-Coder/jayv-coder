# Supabase como fonte dos dados — plano de implementação

> **Para agentes:** use superpowers:executing-plans para executar tarefa por
> tarefa. Os passos usam `- [ ]` para acompanhar.

**Objetivo:** o Supabase vira a fonte dos dados do JayV, com o SQLite como
cache local e fila de saída, login no React e validação no Rust.

**Arquitetura:** o React faz o login com `supabase-js` (PKCE) e entrega o token
ao Rust. O Rust valida o JWT (ES256/JWKS), abre o SQLite do usuário e
sincroniza com o PostgREST por um cliente próprio sobre `reqwest`. Gatilhos no
SQLite registram cada escrita na `outbox`, sem tocar em cada método do
`WorkspaceStore`. O Jev passa a ser uma Edge Function que guarda a chave da
TypeSafe.

**Stack:** Rust (Tauri 2, rusqlite, reqwest, jsonwebtoken), React 19 +
`@supabase/supabase-js`, Postgres/PostgREST, Deno (Edge Function), pgTAP.

**Spec:** `docs/superpowers/specs/2026-09-30-supabase-design.md`

## Ajustes ao spec descobertos no código

1. **Colunas de sincronização com outro nome.** `chats.updated_at` e
   `llm_agents.updated_at` já existem com significado de aplicativo. As colunas
   de sincronia se chamam `row_updated_at`, `row_deleted_at` e `synced_at`, e
   existem em **todas** as tabelas remotas: turnos, checks de entrada e
   perguntas também são reescritos, então "só acrescentar" não vale para
   nenhuma tabela.
2. **O `updated_at` local não é mantido por coluna.** A `outbox` guarda o
   instante da escrita, que vai como `row_updated_at`. Ao baixar, uma linha com
   escrita local pendente é ignorada: quem decide é o servidor, na subida.
3. **`root_path` continua em `projects` no SQLite**, só que fora da lista de
   colunas sincronizadas, em vez de uma tabela `local_paths`. O mesmo vale para
   `turns.partial`, o rascunho do streaming.
4. **Os turnos têm dono.** `turns.local` (1 = criado nesta máquina) impede que
   duas máquinas atendam o mesmo pedido: `claim_next_turn` só pega os locais.
5. **`messages` ganha `uid`.** O id local continua inteiro, para a ordem. O
   `uid` é o id remoto, e a ordem passa a ser `created_at,id`.
6. **Parâmetros do Jev têm padrão.** As constantes atuais continuam no Rust como
   padrão; o valor do cache as substitui quando é válido. A queda para a
   heurística só acontece quando falta pergunta, que agora é problema da função.
7. **Colunas espelhadas.** TEXT vira `text` e INTEGER vira `bigint`, sem
   conversão. Só as três colunas de sincronia usam `timestamptz`.
8. **O app começa sem usuário.** O `WorkspaceStore` abre em memória, é trocado
   pelo arquivo do usuário em `set_session` e volta para a memória no logout.
9. **A Edge Function não usa a service role.** O uso diário é contado por uma
   função `security definer`, `jev_take_call()`, chamada com o JWT do usuário.
   A função é publicada com `verify_jwt = false` e valida o token por
   `auth.getClaims`, que entende as chaves ES256.
